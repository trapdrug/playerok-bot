# Playerok Telegram Bot

Автоматизация продавца на Playerok: отслеживание продаж, уведомления о сообщениях в чате, автовыставление лотов и оплата буста с основного баланса.

## Стек

- Python 3.11+
- aiogram 3 (Telegram бот)
- SQLAlchemy 2 + aiosqlite (SQLite)
- APScheduler (планировщик циклов)
- Playwright (взаимодействие с Playerok)
- cryptography (Fernet шифрование cookies)
- bcrypt (хэширование паролей)
- pydantic-settings (конфигурация из `.env`)

## Быстрый старт

### 1. Клонирование и конфигурация

```bash
cp .env.example .env
# Отредактируйте .env: укажите BOT_TOKEN, FERNET_KEY, ADMIN_INITIAL_PASSWORD и т.д.
```

### 2. Генерация FERNET_KEY

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Установите полученное значение в `FERNET_KEY` в `.env`.

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Запуск без Docker

```bash
python -m app.main
```

### 5. Запуск через Docker Compose

```bash
docker-compose up -d --build
docker-compose logs -f
```

## Роли аккаунтов

| Роль | Что доступно |
|------|--------------|
| Главный администратор | Всё: аккаунты, cookies, настройки автоматизации, LIVE-режим |
| Пользователь | Настройки автоматизации, статус, логи, лимиты. Не видит cookies и не создаёт аккаунты |
| Работник | Только личные уведомления: включить/выключить их в `/settings`. Больше ничего |

- Уведомления — **персональные**: каждый пользователь отключает их у себя, глобального переключателя нет.
- Критические события (сессия истекла, капча, 429, смена вёрстки) всегда приходят главному администратору.

## Настройки (inline-кнопки)

В `/settings` доступны переключатели:

1. **Мои уведомления** — личный переключатель уведомлений (только для вашего аккаунта).
2. **Автовыставление** — создавать новое объявление-копию проданного лота.
3. **Автовыставление с бустом** — сразу выставлять копию с премиумом за счёт основного баланса.
4. **Тестовый режим** — dry-run: ничего не публикуется и не оплачивается, только логируются намерения.

### Важно про тестовый режим / LIVE

- По умолчанию `DRY_RUN=true` — бот ничего не публикует и не оплачивает.
- Переключить в LIVE может только главный администратор (`/dryrun off` + подтверждение).
- В LIVE-режиме бот оплачивает буст только с **основного баланса**. Если источник — заморозка, карта, СБП и т.д., буст откладывается, а не оплачивается.
- Лимит цены одного буста (`/boost_limit`, по умолчанию 925 ₽) считается от **цены буста**. Если цену буста определить не удалось, бот берёт цену товара **без скидки** (`rawPrice`), поэтому товар «100 000 ₽ со скидкой до 100 ₽» не обходит лимит.

## Cookies

Администратор загружает JSON-файл с cookies через Telegram. Бот:
1. Удаляет сообщение с файлом.
2. Шифрует cookies через Fernet (ключ из `.env`).
3. Сохраняет в БД.
4. Проверяет сессию на Playerok.

Сессия проверяется **перед каждым циклом**. Если истекла — все задачи останавливаются, администраторы получают уведомление.

## Автоматизация

Цикл (каждые `POLL_INTERVAL_SECONDS`):

1. Проверка сессии Playerok. Если недействительна — стоп всех задач + уведомление.
2. Получение продаж через GraphQL Playerok (через Playwright страницу с cookies).
3. Счётчик товаров в продаже (GraphQL-операция `items`) — показывается в `/status`.
4. Проверка чатов Playerok: новые непрочитанные личные сообщения → уведомление с никнеймом отправителя и числом непрочитанных.
5. Если `sales_initialized` не установлен — первая проверка помечает существующие продажи как "baseline" без действий (предотвращает массовый релизт истории).
6. Для новых продаж:
   - Уведомление о продаже.
   - Если включено автовыставление или автобуст — бот читает данные проданного лота (операция `item`) и **создаёт новое объявление** с тем же названием, описанием, картинкой, ценой и характеристикой (мутация `createItem`). Кнопка Playerok «Выставить повторно» не используется: она лишь реактивирует старый лот.
   - Новое объявление **публикуется сразу** (мутация `publishItem`).
   - **Премиум покупается отдельным шагом** (мутация `increaseItemPriorityStatus` — та же, что использует сайт): сначала Playerok должен **обработать** новое объявление. Пока оно в статусе `PENDING_APPROVAL`, бот **каждую минуту** проверяет его состояние и, как только объявление вышло в продажу, покупает премиум с основного баланса (`transactionProviderId: LOCAL`). Если премиум не применён — объявление остаётся без буста, но это фиксируется честно: бот проверяет, что приоритет реально стал `PREMIUM`, и считает потраченное как разницу баланса.
   - Если премиум пропущен (лимит `/boost_limit`, триггер названия, автобуст выключен) — объявление всё равно выходит в продажу, просто **без премиума**.
   - Все эти операции выполняются **через API**, без открытия страниц Playerok: бот укладывается в 1 ГБ RAM и работает быстро.
   - Если название товара попадает под **триггер** из `selectors.yaml` → `boost.skip_titles`
     (по умолчанию «доплата подарка» и «доплата подарок») — буст не покупается,
     объявление публикуется без премиума. Сравнение регистронезависимое, по подстроке.
7. Повтор отложенных бустов (с ограничением попыток и интервалом).

### Уведомления о чатах

- Отслеживаются только личные чаты (`PM`); системные уведомления и поддержка пропускаются.
- Уведомление содержит никнейм отправителя, число непрочитанных и время последнего сообщения.
- Текст сообщения в Telegram не пересылается.
- Повторных уведомлений нет: последний ID сообщения хранится в таблице `chat_state`.
- Операция `userChats` и её persisted-query hash заданы в `selectors.yaml` (`graphql.chats_operation`, `graphql.chats_sha256`).

### Защита платежей

- Источник списания проверяется перед каждой оплатой.
- Оплата только с основного баланса. Иначе — откладывается (PendingBoost).
- Триггеры названий (`selectors.yaml` → `boost.skip_titles`): для таких товаров буст
  не покупается, объявление публикуется без премиума. Список можно дополнять.
- Два лимита: дневной (`/limit`) и лимит цены одного буста (`/boost_limit`).
  - Лимит одного буста считается от **цены буста** (то, что списывается с баланса).
    Если цену буста не удалось прочитать, используется цена товара **без скидки**
    (`rawPrice`), поэтому товар «100 000 ₽ со скидкой до 100 ₽» лимит не обходит.
  - Превышение лимита одного буста **не выключает автобуст**: этот товар всё равно
    выставляется в продажу, просто **без премиума** (мутация `publishItem` с обычным
    статусом «Обычный»).
  - Если автобуст выключен вовсе — новое объявление тоже публикуется, но без премиума.
- Если дневной лимит исчерпан — автобуст отключается, уведомление.
- Неопределённый результат оплаты — стоп всех задач, уведомление, не повторяется вслепую.

### Капча / 429 / изменение вёрстки

- Задача останавливается, администраторы уведомляются.
- Бот не повторяет действия вслепую.

## Безопасность

- Пароли хэшируются через bcrypt (12 раундов).
- Cookies шифруются через Fernet. Никогда не логируются.
- Сообщения с паролями и файлами cookies удаляются сразу.
- БOT_TOKEN и пароли не попадают в логи (реdaction-фильтр).
- Блокировка после 5 неудачных попыток входа на 15 минут.
- Вход только в личном чате.
- Основной администратор создаётся при первом запуске из `.env` с обязательной сменой пароля.

### Память

Сервис нормально работает на **1 ГБ RAM**, но на 2–8 ГБ работает ещё быстрее: бот
не открывает тяжёлые страницы Playerok (картинки не грузятся, все операции идут через API),
а браузер перезапускается каждые несколько циклов. В покое бот занимает ~160 МБ.

Настройки, влияющие на это:
- `BLOCK_IMAGES` — не грузить картинки (по умолчанию `false`, то есть грузятся);
- `CYCLE_TIMEOUT_SECONDS` — максимальная длительность цикла, после него цикл прерывается (по умолчанию 300 с);
- `BROWSER_RESTART_CYCLES` — как часто перезапускать браузер (по умолчанию 5).

Если захотите больше запас — **Settings → Replica Limits → Memory** (2–8 ГБ), CPU 2 vCPU достаточно.

## Важные примечания

- Нет регистрации через бота. Аккаунты создаёт только главный администратор.
- При первом входе любого аккаунта требуется смена пароля (минимум 8 символов).
- Регистрация новых аккаунтов Playerok не поддерживается — только привязка существующих через cookies.
- В сухом режиме (dry-run) бот никуда не платит, только регистрирует намерения.
- Реальные CSS-селекторы Playerok могут меняться — обновляйте `selectors.yaml` без пересборки.
